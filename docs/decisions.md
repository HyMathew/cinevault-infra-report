# Décisions d'ingénierie et vérifications

Les choix ci-dessous décrivent la réalisation, ses alternatives et ses limites. Les obligations du sujet ne sont pas présentées comme des optimisations démontrées. Les [campagnes datées](validation-current.md), [preuves pédagogiques](pedagogical-validation.md) et [exemples exécutables](examples/README.md) donnent les révisions et portées.

| Décision / problème | Alternatives et choix | Réalisation et vérification | Limite |
|---|---|---|---|
| Présentation imposée en Flask/Jinja | Templates serveur conservés ; une SPA aurait remplacé une exigence | Routes, formulaires et28templates ; exercices A/B/C réels et suite web159 | Chaque interaction implique une requête ; aucun gain de performance SPA revendiqué |
| Stockage principal JSON | SGBD transactionnel pertinent à une autre charge, mais hors contrainte ; document v2 choisi | Schémas et validateurs, fichier temporaire/fsync/remplacement, tests stockage et reprise | Verrou et document entier limitent la capacité ; aucun benchmark de production |
| Concurrence entre workers | Verrou de thread insuffisant ; verrou fichier interprocessus sur tout read-modify-write | Deux workers Gunicorn ; tests multiprocessus et course réelle d'attribution200/409 | Protection locale au même hôte ; ne partage pas des fichiers entre nœuds |
| Une API sur le propriétaire du volume | Réplicas avec volumes locaux divergents rejetés | Placement explicite, une tâche et volume local ; recréation API avec persistance | Nœud et disque uniques, sans HA |
| Manager dédié | Co-localiser les applications restait possible ; Drain sépare les rôles avec ressources mesurées | Trois VM,2CPU/environ1966Mio chacune, Leader/Drain et workers placés | Manager unique ; pas de tolérance à sa perte |
| Développement monté / runtime immuable | Le bind de code sert le sujet ; l'image embarquée identifie une version déployée | Compose avec2binds readonly et volume data ; Swarm par digests | Le montage ne signifie pas hot reload ; l'image seule ne prouve pas le montage pédagogique |
| Distribution par GHCR | Préchargement SFTP vérifié initialement, puis registre public pour les nœuds | CI, manifeste brut/config, pulls anonymes sur3VM, tâches vérifiées | Dépendance au registre pour un nœud sans cache ; digest n'est pas signature d'auteur |
| Secrets stables et séparés | Valeurs dans YAML/code exclues ; trois secrets à fonctions distinctes | Fichiers Docker0400/UID10001 ; mêmes identités après mise à jour | Reprise des secrets reste privée ; le réseau interne ne remplace pas une autorisation |
| Coût d'inscription et origine du visiteur | Hachage sans admission et IP de proxy commune ont produit deux constats | Admission persistée avant Argon2 et HMAC du contexte exact ; tests/revue/Compose171 puis déploiements | Connexion Argon2 encore sous verrou métier ; pas d'immunité DDoS générale |
| Écriture conditionnelle / rejeu | If-Match empêche une écriture périmée ; clé d'import empêche un lot répété | ETags,412/428, reçu et mutations du lot dans même transaction ; tests de corruption/rejeu | Une erreur après commit impose de lire l'état, pas une relance automatique aveugle |
| Métadonnées sans clé de fournisseur | Wikimedia retenu au lieu d'un service nécessitant une clé non fournie | Cache/quota/verrou distinct, User-Agent ; vrais recherche/aperçu distants | Disponibilité et droits à examiner par média ; données proposées à vérifier |
| Frontière JSON native | Décodage seul insuffisant ; validation structurelle des champs consommés plutôt que copie de tout le métier | Formes invalides,204 et Unicode contrôlés ;74cas ajoutés,159tests sur deux OS, image réellement déployée | Clients injectés inchangés ; pas de validation de tout champ inconnu |
| Contraste sans refonte graphique | Réutiliser le jeton secondaire existant et fixer l'opacité | Placeholders3,56→8,99:1 mesurés après déploiement ; Tab14,390/820px et recherche réels | QA ciblée, sans certification WCAG exhaustive |
| CI Windows et Ubuntu | Les essais Windows seuls n'avaient pas révélé les permissions0600 de l'archive scanner | CI Linux rouge, correction0444 du seul fichier temporaire, jobs suivants verts | Les vulnérabilités Medium/Low restent déclarées ; les bases de scan évoluent |
| Rapport portable Typst | Préférence utilisateur, diagrammes vectoriels et sources éditables ; ancienne génération provisoire conservée comme historique | Compilateur0.15.1 officiel vérifié, polices embarquées, date de référence fixe, compilation réelle | Compilation et égalité d'empreinte ne remplacent pas la lecture de toutes les pages |
| Reprise sur une nouvelle cible | Écraser l'unique magasin ou réintroduire d'anciens accès rejeté | Snapshot/restore isolé, secrets neutralisés dans les exemples, contrôles de corruption | Pas de reprise mesurée après perte du disque du laboratoire ; aucun RTO/RPO garanti |
| Transport d'administration | VPN et SSH strict disponibles, sans domaine/HTTPS public supposé | Clés hôtes comparées aux consoles, clés utilisateur, accès local et tunnel loopback | Cookie Secure=false lié au contexte HTTP de laboratoire ; données synthétiques uniquement |

Les mesures de durée et de charge ne sont pas extrapolées. Les chiffres de tests se rapportent à leurs exécutions ; aucune alternative non construite n'est annoncée plus lente, moins sûre ou moins fiable sur la seule base d'une préférence.
